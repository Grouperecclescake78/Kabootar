# Platform setup

studchat's app code (`lib/`), tests, and the mesh-critical native config are in
the repo. The rest of the native shell — Gradle wrapper, `MainActivity`, the
Xcode project, launcher icons — is generated by Flutter so it stays pinned to
whatever Flutter version you build with, rather than drifting in git.

## One-time bootstrap

From the repo root, with [Flutter](https://docs.flutter.dev/get-started/install)
installed:

```bash
flutter create . --platforms=android,ios --org dev.studchat
flutter pub get
```

`flutter create .` fills in the generated shell **without overwriting** the
files already committed here:

- `android/app/src/main/AndroidManifest.xml` — mesh permissions (Bluetooth,
  location, nearby-Wi-Fi).
- `ios/Runner/Info.plist` — local-network + Bluetooth usage strings and the
  Bonjour service declaration Multipeer needs.

## Minimum platform versions

`flutter_nearby_connections` requires:

| Platform | Minimum |
| -------- | ------- |
| Android  | `minSdkVersion 21` |
| iOS      | `12.0` |

After the first `flutter create`, set these:

- **Android** — in `android/app/build.gradle`, `defaultConfig { minSdkVersion 21 }`.
- **iOS** — in `ios/Podfile`, `platform :ios, '12.0'`, then `cd ios && pod install`.

## Run it

```bash
flutter run                 # on a connected device
```

The mesh needs **two physical devices on the same OS family** to demonstrate
delivery (Android⇄Android or iOS⇄iOS — see the README on the cross-platform
wall). Emulators have no real Bluetooth/Wi-Fi radios, so peer discovery will not
work on them.

## Verify the routing logic without a device

The store-and-forward engine is framework-free and fully covered by a
dependency-free harness that needs only the Dart SDK:

```bash
dart run tool/engine_check.dart
```

See [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) for what it proves.
